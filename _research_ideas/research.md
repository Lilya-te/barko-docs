# План сбора C-BARQ(S) через Яндекс Форму

Пилотный сбор данных для Barko: владельцы пристроенных собак заполняют анкету по ссылке. Канал MVP — **Яндекс Формы** (не Google Forms: доступ и 152‑ФЗ для РФ). Telegram-бот и live-запись в БД откладываем; позже CSV → ingest в Postgres ([research-data-app](../wiki/concepts/research-data-app.md)).

Версия анкеты: **гибрид** — общие вопросы + **42 пункта C-BARQ(S)**.

Источники текстов и состава пунктов:

- русские формулировки: [`QUESTS/c-barq_rus_Bru.pdf`](../QUESTS/c-barq_rus_Bru.pdf);
- short-форма: [`QUESTS/CBARQ_short-final_copy.pdf`](../QUESTS/CBARQ_short-final_copy.pdf);
- mapping 42 пунктов: Duffy 2014 / Wilkins 2024 ([supplement S1](../analytics/research/datatsets/foreign/wilkins_2024_shortened_cbarq_validation_supplement_s1.csv)).

## 1. Цель и границы

- Цель: ответы копятся в Яндекс Формах, затем выгружаются в Postgres для research/K3.
- Лицензия: C-BARQ © Serpell — research use; публичный dump item-текстов не делаем.

## 2. Стек

| Слой | Выбор |
|------|--------|
| Анкета | Яндекс Формы |
| Хранение сырых ответов | ответы формы + периодический CSV/XLSX export |
| Целевая БД | Postgres (research-data-app), позже |
| Ingest | скрипт/ноутбук: CSV → `dogs` / `consents` / `questionnaire_sessions` / `answer_events` |
| Раздача | ссылка приютам и владельцам (чат, почта, QR) |

## 3. Структура формы

```text
Инфо об исследовании
  → Согласие (152-ФЗ)
      → [нет] Стоп без сбора анкеты
      → [да] Контакт владельца
           → Общие вопросы (+ приют, дата дома)
           → C-BARQ(S) 42 пункта
           → Спасибо
```

1. **Инфо об исследовании** — Barko / адаптация пристроенных собак; собака ≥6 месяцев; ~10 минут; контакты Barko (не HUJI из исходного PDF).
2. **Согласие на обработку ПДн** — обязательный выбор «согласен / не согласен»; при отказе — ветка без сбора анкеты. В тексте согласия зафиксировать версию (например `consent_v1`) → позже `consents.version`. Нормы и чеклист: [personal-data-152-fz](../wiki/concepts/personal-data-152-fz.md).
3. **Контакт** — email, телефон, тг-аккаунт (уточнения и повторные волны); не опираться только на аккаунт Яндекса.
4. **Общие вопросы** — см. ниже.
5. **C-BARQ(S) 42** — шкалы как в оригинале; вариант «Не наблюдалось или неприменимо» там, где он есть в C-BARQ.
6. **Спасибо** — согласие на контакт для волны через N дней.

## 4. Общие вопросы

Из предварительного блока русской C-BARQ:

- кличка, 
- возраст, 
- пол, 
- кастрация/стерилизация;
- метис/породистый
- порода;
- вес (кг), 
- рост в холке (опц.);
- сколько собак в доме;
- есть ли другие животные;
- состав семьи;
- где живёт;
- из какого приюта собака (список известных приютов + «Другой» + текстовое поле);
- дата, когда собака приехала домой (тип «дата»).
- что известно о жизни до приюта/дома (свободный текст).

## 5. Поведенческий блок C-BARQ(S)

- В форме ровно **42** пункта short-формы.
- Русские тексты — по соответствию пунктам полной C-BARQ (`global_number`).
- Перед сборкой формы: таблица `global_number → RU text → domain → тип шкалы` — [wiki/concepts/pilot-questionnaire.md](../wiki/concepts/pilot-questionnaire.md).
- В Яндекс Формах: один выбор (radio) для шкал частоты / 0–4 / N/A.
- Разделы по доменам — для удобства заполнения.
- Reverse-coded trainability учитывать при ingest/скоринге, не в UI формы.
- Целевой slug в БД: `cbarq_s_42`.

## 6. Данные

Пока Postgres не готов: хранить CSV export + словарь кодировок шкал. После старта пилота не менять формулировки пунктов без новой `version` формы.

## 7. UX и настройки формы

- Прогресс-бар; обязательные поля пометить.
- Возраст <6 мес — предупреждение в инфо; по возможности ветка «вернитесь позже».
- Не форсировать один ответ на человека (несколько собак у владельца): различать по кличке + дате приезда домой.
- Название и описание — нейтральные, research; без коммерческого позиционирования C-BARQ.

## 8. Этапы работ

1. Составить таблицу 42 пунктов: `global_number` ↔ RU-текст ↔ шкала.
2. Набросать текст инфо + согласия (`consent_v1`).
3. Собрать Яндекс Форму: инфо → согласие → контакт → общие (+ приют, дата дома) → 42 пункта → спасибо.
3.1 Валидировать с экспертами.
4. Пробный прогон 2–3 людьми (время, обрывы, непонятные шкалы).
5. Раздать ссылку пилотной группе (5–15 владельцев).
6. Экспорт CSV; зафиксировать схему колонок здесь или рядом.
7. Когда появится research-data-app — скрипт ingest CSV → Postgres (`cbarq_s_42`).
8. Telegram-бот для напоминаний о волнах и отправки ссылок анкет.

## 9. Критерий готовности

- Форма опубликована; полный путь проходится без тупиков.
- В каждом ответе: согласие, контакт, приют, дата приезда домой, 42 поведенческих пункта (или N/A).
- Есть выгрузка CSV и маппинг колонок → будущая схема БД.
- Пилот ≥5 заполненных анкет; среднее время и drop-off зафиксированы заметкой ниже.
