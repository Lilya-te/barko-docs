| **РКФ Т2** | Расширенный стресс-тест: резкие звуки, угроза, выдержка, самоконтроль | RU | Оригинал на русском | Усложнённая оценка психики для разведения/работы |

| **VIDOPET** | Опросник + батарея поведенческих тестов; 5 факторов (общительность, смелость, агрессия, обучаемость, зависимость от человека) | EN / DE (Vienna) | Personality + lab/field battery |

| **LSSS** | Звукобоязнь (гроза, салюты и др.) | EN | Клиника noise sensitivity |
| **Dog-ADHD RS** | Гиперактивность, невнимательность, импульсивность (аналог ADHD-рейтинга) | EN | Нет устойчивого валидированного RU | Скрининг ADHD-like паттернов |
| **CADES / CCDR / CCAS** | Скрининг когнитивной дисфункции у пожилых собак | EN | Нет валидированного RU | Гериатрия, CDS / «собачья деменция» | Нет крупных открытых датасетов в каталоге Hvostun |

## C-BARQ данные

Рисерч данных анкет C-BARQ показал множество данных:

- база UPenn (более 50К собак, доступ по запросу)
- открытые данные исследователей (найдено 36К до очистки)
- полуоткрытые - доступ по запросу исследователям. Не все отвечают
- Юрий Гербек собрал около 2К строк, но так как исследование еще не опубликовано не запращивали

Подходящие нам данные (собаки после приюта в период адаптации). Таких данных гораздо меньше:

- Bohland 337 строк (99 собак) - открытые
- Serpell & Powell 619 строк (562 собаки) - получены по запросу

**Итого данных** 956 строк = 619 Serpell + 337 Bohland

## Структура C-BARQ(Mini)

Mini C-BARQ scoring method

The mini C-BARQ provides a set of quantitative scores for the following fourteen different subscales or categories of behavior:

- Excitability
- Stranger-directed aggression
- Owner-directed aggression 
- Dog-directed aggression
- Familiar dog aggression
- Stranger-directed fear
- Nonsocial fear
- Dog-directed fear
- Touch sensitivity 
- Separation-related behavior
- Attachment and attention-seeking
- Training difficulty
- Chasing
- Energy level

The mini C-BARQ also provides useful information on the occurrence of an additional 9 miscellaneous behavior problems ranging from escaping and roaming to persistent barking.

Each subscale is represented by a small number of 5-point scales (questions). Some are graduated scales that measure severity of particular behaviors (e.g. aggression) and are numbered from 0–4 in the questionnaire. The remainder are frequency scales which should be scored as: Never = 0, Seldom = 1, Sometimes = 2, Usually = 3 and Always = 4, except for questions 27 & 28 in Section 6. FOR THESE QUESTIONS ONLY, reverse the scores to: Never = 4, Seldom = 3, etc.

To calculate behavior subscale scores, use the following formulae:

- “Excitability” score = Sum of scores for questionnaire items 1 + 2 ÷ 2 (i.e. items 1 + 2)/2.
- “Stranger-directed aggression” score = (items 3 + 6 + 9)/3
- “Owner-directed aggression” score = (items 4 + 5 + 7)/3
- “Dog-directed aggression” score = (items 8 + 10)/2 
- “Dog rivalry/Familiar dog aggression” score = (items 11 + 12)/2
- “Stranger-directed fear” score= (items 13 + 15)/2
- “Nonsocial fear” score = (items 14 + 16 + 18)/3
- “Dog-directed fear” score = (items 17 + 19)/2
- “Touch sensitivity” score = (items 20 + 21)/2
- “Separation-related problems” score = (items 22 + 23 + 24)/3
- “Attachment/attention-seeking” score = (items  25 + 26)/2
- “Training difficulty” score = (items 27 + 28 + 29)/3 — remember to reverse scoring order for items 27 & 28 (see above).
- “Chasing” score = (items 30 + 31)/2
- “Energy” score = (items 39 + 40)/2
- “Miscellaneous” items other than those listed above are optional, and can be removed from the questionnaire as desired. If retained, they should be scored individually, 0–4.

## Выбор метрик

Постановка: multilabel / multi-label multi-output — из каталога N ≈ 40 выбрать набор рекомендаций (часто |P| = |G| = 5). Эталон G — экспертная разметка. 

| Метрика | Что измеряет | Формула / идея | Плюсы | Минусы | Для Hvostun (top-5, N≈40) |
|---------|--------------|----------------|-------|--------|---------------------------|
| **Example-F1** (Example = анкета) | Совпадение множеств P и G **на одной анкете**, затем среднее по выборке | TP = card(P ∩ G); при card(P)=card(G)=k: F1 = TP/k; macro = mean по i | Понятна эксперту («верно 3 из 5»); совпадает с H₁ | Путаница с sklearn `macro-F1` (там — по лейблам) | **Основная** для H₁-baseline / H₁-plan; порог ≥ 0,6 |
| **Micro-F1** | Глобально суммирует TP/FP/FN по всем лейблам и объектам | Один F1 на весь пул предсказаний | Устойчива при редких лейблах; стандарт multilabel | Маскирует провалы редких рекомендаций; при фиксированном k близка к example-F1 | Вторичная; отчёт рядом с основной |
| **Macro-F1 (label-averaged)** | F1 **по каждому пункту каталога**, затем среднее по N лейблам | F1_j на бинарной задаче «лейбл j вкл/выкл», mean_j | Честна к редким рекомендациям | При N=40 и малом n много лейблов с 0 support → нестабильна | Вторичная после накопления разметки; не путать с example-F1 |
| **Precision@k / Recall@k / F1@k** | Качество top-k выдачи | P@k = card(P ∩ G)/k; R@k = card(P ∩ G)/card(G); F1@k — гармоника | Стандарт ranking/recommendation; явный k | Нужен ranking/scores; при card(G)≠k Recall и Precision расходятся | Если card(G)≠5 или модель даёт scores — брать F1@k / R@k |
| **Jaccard (IoU)** | Доля пересечения множеств | card(P ∩ G) / card(P ∪ G) | Классика set-overlap; ∈[0,1] | При card(P)=card(G)=k связана с F1, но шкала другая (строго ≤ F1) | Можно дублировать example-F1; не обязательна как primary |
| **Hamming loss** | Доля ошибочных битов по всем лейблам | mean (предсказано ≠ истина) по N лейблам | Стандарт sklearn multilabel | При k≪N почти всё — true negatives → loss ≈ 0 даже у слабой модели | **Плохо подходит** как sole metric при sparse top-5 |
| **Subset accuracy** (exact match) | Полное совпадение набора P = G | 1 если множества равны, иначе 0; mean | Жёсткий «идеальный» критерий | При card(G)=5 из 40 почти всегда 0; нечувствительна к «4 из 5» | Только как доп. «доля идеальных»; не для H₀ |
| **LRAP** (Label Ranking Average Precision) | Качество **ранжирования** лейблов | Насколько релевантные лейблы выше в ранге | Учитывает scores, не только hard top-k | Нужны вероятности/ранги; сложнее объяснить комиссии | Если ML выдаёт scores — доп. метрика сравнения моделей |
| **Coverage error** | Насколько глубоко в ранге нужно спуститься, чтобы покрыть все истинные лейблы | Средний ранг «самого нижнего» релевантного | Полезна для ranking | Не интерпретируется как «3 из 5 верных» | Опционально при сравнении rankers |
| **Random baseline F1** | Нижняя граница | При N=40, k=5 без возвращения: E[TP]/5 = (5·5/40)/5 = **0,125** | Якорь для H₁-baseline | Не метрика модели, а эталон | Обязательный столбец в таблицах сравнения |

- Primary **example-F1**; 
- Рядом micro-F1 и random 0,125; 
- После накопления разметки — label-macro-F1 по пунктам каталога;
- Дополнительные Precision@k / LRAP.

## Расчет случайного выбора 5 рандомных рекомендаций

**Условия:** каталог размера $N = 40$; эталон эксперта $G$, $\lvert G\rvert = k = 5$; предсказание $P$ — равномерный случайный набор из $k = 5$ пунктов **без возвращения** (все $\binom{N}{k}$ наборов равновероятны).

**Число верных попаданий** на одной анкете:

$$
TP = \lvert P \cap G \rvert.
$$

Случайная величина $TP$ имеет гипергеометрическое распределение:

$$
TP \sim \mathrm{Hypergeometric}(N=40,\; K=\lvert G\rvert=5,\; n=\lvert P\rvert=5),
$$

$$
\mathbb{P}(TP = t) = \frac{\binom{K}{t}\binom{N-K}{n-t}}{\binom{N}{n}}, \quad t = 0,1,\ldots,\min(K,n).
$$

**Математическое ожидание TP:**

$$
\mathbb{E}[TP] = n \cdot \frac{K}{N} = 5 \cdot \frac{5}{40} = \frac{25}{40} = 0.625.
$$

**Example-F1** при $\lvert P\rvert=\lvert G\rvert=k$ (как в H₁):

$$
F1 = \frac{2\cdot TP}{\lvert P\rvert+\lvert G\rvert} = \frac{TP}{k} = \frac{TP}{5}
$$

(здесь Precision = Recall = $TP/k$, поэтому F1 = $TP/k$).

**Ожидаемый F1 случайного выбора:**

$$
\mathbb{E}[F1] = \frac{\mathbb{E}[TP]}{k} = \frac{n\cdot K/N}{k} = \frac{K}{N} = \frac{5}{40} = 0.125.
$$

В общем виде при $\lvert P\rvert=\lvert G\rvert=k$:

$$
\mathbb{E}[F1_{\mathrm{random}}] = \frac{k}{N}.
$$

**Проверка через Precision/Recall:**  
$\mathbb{E}[\mathrm{Precision}] = \mathbb{E}[TP]/k = K/N$, $\mathbb{E}[\mathrm{Recall}] = \mathbb{E}[TP]/K = n/N$; при $n=k$ оба равны $k/N$, и $\mathbb{E}[F1] = k/N$.

**Итог для гипотез:** random baseline **F1 = 0,125** (в среднем верно $0.625$ из 5 ≈ меньше одного пункта). Порог H₁-baseline (macro example-F1 ≥ 0,6) выше случайного в $0.6 / 0.125 = 4.8$ раза.

## Расчет минимального значения — 3/5

Порог «верно не менее 3 из 5» при $\lvert P\rvert=\lvert G\rvert=5$:

$$
F1 = \frac{TP}{5} \ge \frac{3}{5} = 0.6 \quad \Leftrightarrow \quad TP \ge 3.
$$

То есть example-F1 ≥ 0,6 ⇔ на анкете попали ≥ 3 рекомендации из эталона G. Macro-F1 по val — среднее таких $F1_i$; H₀: macro-F1 < 0,6.

## Алгоритм vs ML

Rule-based mapping в H₁-baseline: «домен + порог T → пункт(ы) каталога». Ниже — размер пространства решений при $D = 14$ доменах C-BARQ(Mini) и $N = 40$ рекомендациях.

### Матрица решений (полная)

Ячейка $(d, r)$: для домена $d$ и рекомендации $r$ — один порог $T_{d,r}$: если скор домена $s_d \ge T_{d,r}$, рекомендацию $r$ включаем в кандидаты (иначе — нет).

$$
\text{размер матрицы} = D \times N = 14 \times 40 = 560
$$

$$
\text{число порогов (параметров)} = 560
$$

(по одному вещественному $T_{d,r}$ на ячейку; «не использовать связь» = $T_{d,r} = +\infty$ или отдельный флаг).

Если явно хранить и **бит связи**, и **порог**:

$$
M \in \{0,1\}^{14\times 40},\quad T \in \mathbb{R}^{14\times 40}
\quad\Rightarrow\quad 560 \text{ бит} + 560 \text{ порогов} = 1120 \text{ параметров}.
$$

### Разреженный вариант (реалистичный для эксперта)

На практике у рекомендации 1–3 релевантных домена, не все 14×40.

Пусть $E$ — число активных рёбер «домен → рекомендация» ($\lvert E\rvert \ll 560$). Тогда число порогов = $\lvert E\rvert$.

| Сценарий | E (оценка) | Порогов |
|----------|----------------|--------|
| Полная матрица | 560 | 560 |
| В среднем 2 домена на рекомендацию | 40×2 = 80 | 80 |
| В среднем 1 домен на рекомендацию | 40 | 40 |
| Один общий порог на домен + бинарная маска $M$ | 14 порогов + до 560 бит маски | 14 + size(supp(M)) |

### От скоров к top-5

1. По анкете считаем $s_1,\ldots,s_{14}$.
2. Кандидат $r$ включается, если $\exists\, d:\; M_{d,r}=1 \land s_d \ge T_{d,r}$.
3. Если кандидатов > 5 — отбор top-5 (напр. по $\max_d (s_d - T_{d,r})$ или фиксированный приоритет каталога); если < 5 — добор правилами / оставляем меньше (для метрики H₁ лучше фиксировать P=5).

### Сравнение с ML по числу параметров (порядок)

| Подход | Порядок числа параметров |
|--------|--------------------------|
| Rule-based, полная $T_{d,r}$ | **560** порогов |
| Rule-based, sparse ~2 ребра/рекомендация | **~80** порогов (+ маска) |
| Rule-based, 1 порог на домен + маска | **14** + биты связей |
| LogisticRegression, multilabel one-vs-rest, признаки $p$ (напр. 14 доменов + профиль) | $N \times (p+1) \approx 40\times(14+1) = \mathbf{600}$ (только домены); с профилем больше |
| Decision tree | зависит от глубины / числа листьев; типично десятки–сотни правил |

**Вывод:** полная матрица «14×40 × 1 порог» = **560** степеней свободы — сопоставима с простой LR по доменам (~600), но экспертно **незадаваема** целиком; для H₁-baseline фиксируют разреженный mapping ($\sim 40$–$80$ рёбер) до обучения ML, без подгонки порогов на val.

## Сравнение моделей (LR, DT)

Контекст H₁-plan: multilabel / top-5 из каталога N≈40 по признакам доменов C-BARQ(Mini) (+ профиль). Кандидаты для первого сравнения — **LogisticRegression** (часто one-vs-rest по лейблам) и **DecisionTree** (как в формулировке H₁-plan).

| Критерий | LogisticRegression (LR) | DecisionTree (DT) |
|----------|-------------------------|-------------------|
| **За** | Линейная, стабильна на малых n; мало гиперпараметров; коэффициенты читаемы для кинолога/комиссии («домен ↑ → шанс рекомендации r»); хорошо калибруется (вероятности для ranking → top-5); близка по духу к порогам rule-based | Ловит нелинейности и взаимодействия доменов (если–то); правила в листьях объяснимы; соответствует формулировке H₁-plan; не требует масштабирования признаков |
| **Против** | Не моделирует взаимодействия доменов без ручного feature engineering; при one-vs-rest × 40 лейблов — ~N·(p+1) параметров, на малой разметке легко шум; порог отбора top-5 всё равно нужно задавать снаружи | Легко переобучается (особенно при N=40 лейблах и малом n анкет); нестабильна к смене выборки; глубокое дерево хуже объясняется, чем LR-коэффициенты; вероятности в листьях грубые без pruning/ensembles |
| **Данные** | Лучше при n небольшом, признаках в основном аддитивных (14 скоров) | Нужен больший n или жёсткий `max_depth` / min_samples, иначе F1 на val «врёт» |
| **Интерпретация для эксперта** | «Вес домена» — прямой аналог mapping домен→рекомендация | «Если stranger_fear > 2 и energy > 3 → r17» — близко к rule-based, удобно сверять с каталогом |
| **Связь с baseline** | Естественный soft-upgrade порогов T | Естественный soft-upgrade деревьев правил эксперта |
| **Риск для H₁** | Может **не** обыграть rule-based, если связи линейны и sparse mapping уже хорош | Может обыграть на train и проиграть на val (overfit) → ложное «подтверждение» H₁-plan |

| Итог | Когда брать |
|------|-------------|
| **LR** | Первая ML-линия после rule-based; контроль интерпретируемости и калибровки scores |
| **DT** | Проверка гипотезы о нелинейных правилах; ограничить глубину; сравнивать **на том же val**, что LR и rule |
| **Дальше** | Если оба слабее/на уровне rule → в продукт rule; если DT/LR лучше → H₁-quality; при росте n — RandomForest как устойчивость над DT |

Метрика сравнения та же: **example-F1 (macro по анкетам)** на фиксированном val; рядом micro-F1 и random 0,125.

## Генерация ответов из текста как возможность

**Вход:** сплошной текст — транскрипт голоса (ASR) и/или свободное описание собаки + ответы на уточняющие вопросы.  
**Выход:** черновик пунктов C-BARQ(Mini) (0–4 / N/A) + `confidence` + `evidence_span`; в finished — только после **подтверждения пользователем** (`channel=nlp` / `k5_extract`). Это контур H₁-channel (TOST NLP vs self-report).

### Какие методы попробовать

| Метод | Идея | Плюсы | Минусы / риск | Статус для пилота |
|-------|------|-------|---------------|-------------------|
| **1. Embeddings + cosine (retrieval по шкале)** | Векторный индекс формулировок пунктов и уровней 0–4; куски текста → nearest item/ответ | Прозрачно, дёшево, воспроизводимо; совпадает с методикой Б3 | Плохо ловит отрицания («не кусает»), иронию, «не знаю»; нужен чанкинг | **Первый кандидат** H₁-channel |
| **2. Правила / словарь триггеров** | Ключевые фразы → домен/пункт («лает когда ухожу» → separation) | Быстрый cold start, объяснимо эксперту | Хрупко к формулировкам; покрытие низкое | Дополнение к (1), не sole |
| **3. Классификатор пункта (NLI / zero-shot)** | Гипотеза: «текст влечёт ответ X на вопрос q» (entailment) | Лучше учитывает смысл, чем чистый cosine | Нужна модель NLI; пороги калибровать | Второй эксперимент |
| **4. LLM structured extract** | Промпт: верни JSON `{item_id, value, quote}` по списку незаполненных пунктов | Гибко на разговорном RU; один вызов на абзац | Галлюцинации баллов; стоимость/latency; нестабильность API | Только с обязательным confirm + quote |
| **5. LLM + schema / tool-call** | JSON Schema: item_id ∈ {q01…q42}, value ∈ {0..4,X} | Меньше «левых» пунктов | Всё ещё нужен human confirm | Предпочтительнее свободного LLM |
| **6. Двухэтапный пайплайн** | (A) какие пункты затронуты → (B) какой балл 0–4 | Проще отладка; можно смешать retrieval + LLM | Два шага ошибок | Рабочая архитектура MVP |
| **7. Активный диалог (slot-filling)** | После extract — список «дыр»; бот задаёт только недостающие / низкоуверенные пункты | Снижает трение vs полная форма | Нужен state анкеты; риск уйти от канонических формулировок C-BARQ | **Да, диалог реален** (см. ниже) |

**Препроцессинг голоса:** ASR → текст → те же методы. Ошибки ASR («не лает»↔«лает») критичны — низкий confidence + уточняющий вопрос.

**Не делать:** silent auto-fill finished без confirm; смешивать NLP-ответы с self-report в train без поля `channel`.

### Насколько быстро формировать дополнительные вопросы?

| Слой | Что происходит | Ориентир latency |
|------|----------------|------------------|
| После абзаца / реплики | extract → незаполненные / low-confidence пункты | embeddings+rules: **~50–300 ms**; LLM extract: **1–5 с** |
| Выбор следующего вопроса | приоритет дыр / max uncertainty / порядок Mini | **<50 ms** (без LLM) |
| Формулировка вопроса | шаблон из текста пункта C-BARQ **или** LLM-перефраз | шаблон: мгновенно; LLM: **+1–3 с** |
| Ход «ответ → 1 уточнение» | ASR (опц.) + extract + pick + вопрос | текст без LLM: **обычно <1 с**; с LLM: **2–6 с**; голос: **+ASR** |

Практически: уточнения можно отдавать **сразу после каждой реплики**. Для пилота безопаснее **не генерировать** вопрос LLM-ом, а подставлять канонический текст пункта / шкалу 0–4.

### Можно ли сделать диалог?

**Да.** Это state machine поверх анкеты:

```
свободный текст / голос
    → ASR (опц.)
    → extract (методы 1–6)
    → обновить слоты q01…q42 (draft)
    → если есть дыры или confidence < τ
          → задать 1–3 уточняющих вопроса (шаблон пункта)
    → иначе сводка → user confirm → finished
```

| Режим | Описание | Когда |
|-------|----------|-------|
| **Одноразовый extract** | Рассказ → черновик → правка вручную | Быстрый эксперимент H₁-channel |
| **Полудиалог** | Рассказ + 3–7 уточнений по важным дырам | Пилот UX |
| **Полный слот-диалог** | Бот ведёт до заполненности ≥ порога (напр. 90% / ключевые домены) | Продукт рядом с K5 |

Ограничения: формулировки C-BARQ лучше **не вольно перефразировать** (валидность шкалы); голос и чат — ПДн (согласие, РФ-хостинг, provenance). Оценка канала — TOST доменов NLP vs Яндекс.Форма (H₁-channel).
