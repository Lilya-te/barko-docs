# ФСТЭК № 117 для Hvostun: что делать на практике

Практический слой поверх [fstek-117-info-protection](../sources/fstek-117-info-protection.md). Нормы ПДн: [personal-data-152-fz](personal-data-152-fz.md).

## Вердикт по обязательности

| Контур | Приказ № 117 обязателен? | Что действует |
|--------|--------------------------|---------------|
| Research-пилот (анкеты, Яндекс.Формы, Postgres в РФ) | Нет | 152-ФЗ, ПП № 1119, меры по смыслу приказа ФСТЭК № 21 для ИСПДн |
| Продукт ООО (сайт, K3/K5, ops-БД) | Нет, пока не ГИС/муниципальная ИС | То же + договоры с обработчиками |
| Пилот у муниципального приюта / ГБУ | Косвенно: ИС заказчика может подпадать под № 117 | Передача данных и доступы — по политике заказчика |
| Встраивание в ГИС / госзакупка SaaS для органа власти | Да (для заказчика; к вам — требования ТЗ/контракта) | Полный контур № 117 + аттестация ГИС |

**Не раздувать MVP:** не внедрять аттестацию, сертифицированные СЗИ «под К1» и ГосСОПКА до B2G-контракта. Имеет смысл заложить архитектуру, которую потом не придётся ломать.

## Чеклист MVP (разумный минимум)

Опирается на дух базовых мер п. 63 Требований и на 152-ФЗ, без полного внедрения № 117.

1. **Разделение контуров:** ops (ПДн) vs training (обезличенный export) — см. [research-data-app](research-data-app.md).
2. **Хранение в РФ** при сборе ПДн граждан РФ (ст. 18 ч. 5 152-ФЗ).
3. **Auth и доступы:** учётные записи админов/экспертов; минимум привилегий; нет общих паролей.
4. **Логирование** доступа к ПДн и админ-действиям (кто, когда, что изменил).
5. **Подрядчики** (Яндекс Формы, хостинг, LLM API): поручение обработки / ДПА; в договоре — запрет использовать ПДн для дообучения чужой модели.
6. **Инциденты:** сценарий уведомления Роскомнадзора 24ч / 72ч (ст. 21 152-ФЗ).
7. **K3:** скоры и рекомендации — advisory, не «авторешение о человеке» (ст. 16 152-ФЗ).

## K5 / LLM / RAG (п. 60–61 № 117 и §3.18 методички)

Даже без статуса ГИС эти требования — хороший дизайн-док для чата.

| Требование ФСТЭК | Практика Hvostun |
|------------------|------------------|
| Контроль тематик / форматов запросов и ответов | System prompt + allowlist тем (адаптация, гуманная кинология); отказ вне scope |
| Фильтрация ввода/вывода | Не принимать/не возвращать контакты, адреса, паспортные данные; redaction в логах |
| Детект недостоверных ответов | RAG с цитированием wiki/источников; флаг «нет опоры в базе»; эскалация к эксперту |
| Не отдавать ИОД/ПДн разработчику модели «на улучшение» | API без retention/training; не слать сырые ops-ПДн в промпт; для fine-tune — только обезличенный корпус |
| Защита обучающих данных и RAG | Curated wiki/RAG-корпус отдельно от ops; контроль целостности; без pickle-артефактов из недоверенных источников |
| Доверенные компоненты ИИ | Предпочтение моделям/хостингу с понятной юрисдикцией и договором; документировать выбор |

Явно упомянутые в методичке расширения (**RAG**, LoRA) — это как раз контур K5 и будущего дообучения на обезличенных данных.

## Если появится B2G (муниципалитет / ГБУ приют)

Заранее подготовить ответы на вопросы заказчика:

1. Класс защищённости их ИС (К1–К3) и УЗПДн по ПП № 1119 — **определяет заказчик**, не Hvostun.
2. Нужна ли аттестация их сегмента / вашего модуля.
3. Канал передачи: API в сегменте заказчика vs облако Hvostun в РФ; требования к МЭ, журналам, СЗИ.
4. Доступ сотрудников Hvostun как подрядчиков: регламент, NDA, минимизация прав (п. 58 Требований).
5. Модель угроз — по банку угроз ФСТЭК, если заказчик потребует.

Ориентир для частного сегмента «объектовый + низкий ущерб» часто К3; при ПДн меры К3 закрывают УЗПДн 3–4 по связке методички с № 117. Конкретный класс всегда фиксирует акт заказчика.

## Что сознательно откладываем

- Полный пакет политики/стандартов/регламентов «как у госоргана» (п. 14).
- Подразделение ИБ с 30% профильных специалистов (п. 20).
- Отчёт контроля защищённости в ФСТЭК раз в 3 года (п. 67) — для адресатов Требований.
- Обязательная аттестация (п. 65) — для ГИС.
- Сертифицированные СЗИ 4–6 класса (п. 71–72) до требования в ТЗ.
