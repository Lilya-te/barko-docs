# ML-пайплайн проверки гипотез (Hvostun)

Согласовано с [Б2_гипотезы.md](Б2_гипотезы.md).

## 0. Объект, выборка, разбиение

| Элемент | Фиксация |
|---------|----------|
| Объект | анкета владельца на волне 7–14 дней (C-BARQ Mini / C-BARQ(S)) + профиль собаки |
| Таргет рекомендаций | набор из 5 пунктов каталога (N = 40); эталон — экспертная разметка G |
| Каналы признаков | Яндекс.Форма и/или NLP-заполнение из чата |
| Референс | unified mini-сессии (Bohland + Serpell) / short C-BARQ post-adoption |
| Split | **train** / **val** — референс (Bohland + Serpell); **test** — российские респонденты |

Критерий готовности данных: item-level ответы (или доменные скоры), экспертный эталон рекомендаций на val/test, согласие/версия формы для ops-контура.

## 1. Сбор и подготовка данных

1. **Пилот РФ:** лонгитюдный self-report (неделя / месяц / 3 месяца) через Яндекс.Формы + реестр респондентов; волна 7–14 дней — основная для рекомендаций.
2. **Экспертный контур:** разметка «анкета → рекомендации каталога» (принять / править / отклонить + «безопасна») → обучающие пары и эталон G для macro-F1 / H₁-quality.
3. **Внешние данные:** ingest Bohland/Powell/Serpell → единая схема mini-42 + 14 доменов (harmonization), без смешивания с ПДн пилота в training без обезличивания.
4. **Признаки:** доменные скоры C-BARQ(Mini), пункты q01–q42 при необходимости, профиль (порода / возраст / история приюта и т.п.).
5. **Протокол:** версия анкеты, `channel` заполнения, train/val/test ids — фиксируются до запуска экспериментов.

## 2. Baseline-алгоритм (rule-based) — проверка H₁-baseline

0. Первый черновик самостоятельно, далее вместе с научным консультантом.
1. Зафиксировать mapping «домен + порог T → пункт(ы) каталога» (без подгонки на val).
2. На каждой анкете val выдать ровно 5 рекомендаций (`|P| = |G| = 5`).
3. Метрика на анкету i:

$$
TP_i = \lvert P_i \cap G_i \rvert,\quad \mathrm{F1}_i = \frac{TP_i}{5},\quad \text{macro-F1} = \mathrm{mean}_i(\mathrm{F1}_i)
$$

4. Нижняя граница (случайный выбор 5 из 40):

$$
\mathbb{E}[F1_{\mathrm{random}}] = \frac{5}{40} = 0.125
$$

5. **Решение по H₀:** `macro-F1 < 0.6` → baseline не подтверждён; иначе — эталон для шага 3. Порог 0.6 ≈ «верно не менее 3 из 5».

## 3. Построение и сравнение ML-моделей — H₁-plan-DT и H₁-plan-LR

1. Обучить на train две модели, предсказывающие набор рекомендаций (мультилейбл / top-5):
   - **H₁-plan-DT:** DecisionTree;
   - **H₁-plan-LR:** LogisticRegression **one-vs-rest** (бинарный классификатор на каждый из N = 40 пунктов).
2. На **том же val**, что у rule-based: выдать top-5 (DT — по скорам листьев; LR — по вероятностям OvR), посчитать macro-F1 (та же example-F1, что в H₁-baseline).
3. Сравнить каждую с baseline:

$$
\Delta_{\mathrm{DT}} = \text{macro-F1}_{DT} - \text{macro-F1}_{baseline},\quad
\Delta_{\mathrm{LR}} = \text{macro-F1}_{LR} - \text{macro-F1}_{baseline},\quad
\delta = 0.10
$$

Интерпретация δ: +0.10 macro-F1 ≈ **+0,5 верной рекомендации из 5** на анкету.
4. **Доп. (желательно):** 95% bootstrap CI для Δ_DT и Δ_LR (paired по анкетам); нижняя граница CI > 0 усиливает вывод.
5. **Решение по H₀:** `Δ_DT < 0.10` и `Δ_LR < 0.10` → в продукт идёт rule-based (или доработка); иначе в H₁-quality идёт кандидат с большим Δ (при обоих `≥ 0.10` — лучший).

## 4. Экспертная валидация качества — проверка H₁-quality

Контекст объёма (ориентир): train ≈ 99+66, test ≈ 20 анкет × 5 рекомендаций = 100 оценок. Пороги ниже — реалистичные для НИР-3 при таком n (не aspirational 95%/99% для авто-контура).

1. На отложенных (test) анкетах модель выдаёт top-5 рекомендаций.
2. Кинолог по схеме: принять / править / отклонить (+ флаг «безопасна»).
3. Метрики:

$$
P_{\mathrm{accept}} = \frac{N_{\mathrm{принять}}}{N_{\mathrm{всего\ рекомендаций}}}
$$

править / отклонить не считаются «принять»; отдельно — доля «безопасна».
4. Целевые уровни (Б2): accept ≥ ~60–70%, safe ≥ ~97–98%.
5. **Решение по H₀:** `accept < 60%` или `safe < 97%` → модель не допускается в полуавто-контур без правок эксперта; факт + CI фиксировать в отчёте (при n ≈ 100 порог 99% safe статистически почти не доказуем).

## 5. Наполнение анкеты из текста + векторная база — проверка H₁-channel

Цель: снизить трение заполнения и проверить, что NLP-канал эквивалентен self-report по доменным скорам.

### 5.1. Векторная база формулировок шкалы

1. Индексировать тексты пунктов C-BARQ(Mini) и вариантов ответа / уровней шкалы (0–4) как документы.
2. Построить embeddings (один зафиксированный encoder на весь эксперимент).
3. Хранить в векторном индексе (chunk = формулировка пункта/ответа + metadata: `item_id`, шкала).

### 5.2. Алгоритм заполнения из чата

1. Вход: письменный Q&A или транскрипт голоса владельца.
2. Для релевантных реплик — retrieval по косинусному сходству с формулировками пунктов/ответов.
3. Маппинг top-hit → предложенный балл пункта; пользователь подтверждает (provenance: `channel=k5_extract` / `nlp`, `user_confirmed`).
4. Из заполненных пунктов считаются доменные скоры тем же правилом, что для self-report.

### 5.3. Оценка эквивалентности каналов

#### 5.3.1. Дизайн сбора

1. Параллельный сбор: тот же владелец — self-report **и** NLP-заполнение по тексту (парный дизайн).
2. **Контрбалансировка порядка:** ½ владельцев — сначала форма, ½ — сначала чат; порядок фиксируется в протоколе.
3. **Слепота:** NLP-пайплайн и оператор не видят ответов формы до расчёта скоров.
4. **Два варианта NLP-скоров:** сырой (`user_confirmed = false`) и подтверждённый (`user_confirmed = true`) — подтверждение может «подтягивать» ответы к памяти о форме; основной анализ — по подтверждённым, сырой — как sensitivity.
5. **Test-retest формы** (подвыборка): повторное заполнение формы тем же владельцем через 3–7 дней — для калибровки δ (см. 5.3.3).

#### 5.3.2. Основной критерий — парный TOST по каждому ключевому домену

Для владельца i и домена d:

$$
D_{i,d} = s_{i,d,\mathrm{NLP}} - s_{i,d,\mathrm{self}},\quad \Delta_d = \bar{D}_d
$$

Две односторонние H₀ (парный t-тест, α = 0.05 каждая):

$$
H_{01}: \mu_{D_d} \le -\delta,\qquad H_{02}: \mu_{D_d} \ge +\delta
$$

Эквивалентность по домену d доказана, если отвергнуты **обе**. Эквивалентная формулировка:

$$
\mathrm{CI}_{\text{90\%}}(\bar{D}_d) \subset (-\delta,\ +\delta)
$$

(90%, а не 95%: два односторонних теста по 5%).

**Несколько доменов — intersection–union:** H₁-channel принимается, только если TOST пройден по **каждому** ключевому домену; поправка на множественность не требуется (критерий уже консервативен).

#### 5.3.3. Выбор δ (фиксируется до сбора данных)

Приоритет источников:

1. **Test-retest формы (предпочтительно):** δ = верхняя граница 90% CI для среднего абсолютного retest-расхождения домена «форма vs форма». Логика: NLP-канал не должен расходиться с формой сильнее, чем форма сама с собой.
2. **Через SD домена по референсу** (Bohland / Serpell): δ = 0.3–0.5 · SD_d.
3. **Абсолютный порог на шкале 0–4:** δ = 0.3–0.5 балла с обоснованием кинолога.

Продуктовая проверка δ: при сдвиге доменного скора на δ rule-based mapping «домен + порог T» не должен заметно менять top-5 (доля анкет с изменённым top-5 — фиксировать в отчёте).

#### 5.3.4. Размер выборки

Для парного TOST при истинной разности ≈ 0, α = 0.05, мощность 80%:

$$
n \approx \frac{(z_{0.95} + z_{0.90})^2\,\sigma_D^2}{\delta^2} \approx 8.6\left(\frac{\sigma_D}{\delta}\right)^2
$$

| δ / σ_D | n пар (≈) |
|---|---|
| 0.5 | 35 |
| 0.4 | 54 |
| 0.3 | 96 |

σ_D оценивать по пилоту / test-retest. При n ≈ 20 пар эквивалентность практически не доказуема → честный результат «эквивалентность не доказана», а не «каналы различаются».

#### 5.3.5. Вторичные метрики согласия (не заменяют TOST)

TOST сравнивает только средние; индивидуальное расхождение проверяется отдельно:

| Метрика | Уровень | Ориентир |
|---|---|---|
| ICC(2,1), absolute agreement | доменный скор | ≥ 0.75 (good) |
| Bland–Altman: bias и LoA | доменный скор | LoA = mean(D) ± 1.96 · SD(D); bias внутри ±δ |
| Weighted Cohen's κ (quadratic) | пункты q01–q42 | ≥ 0.6; список «плохих» пунктов → доработка формулировок индекса |
| Coverage | пункты / домен | доля пунктов, заполненных NLP; домен в анализе только при coverage ≥ 80% пунктов домена |

#### 5.3.6. Решение по H₀

- **H₀ сохраняется**, если хотя бы по одному ключевому домену TOST не пройден (`|Δ| ≥ δ` или CI₉₀ выходит за ±δ) → NLP-канал не заменяет форму без доработки.
- При пройденном TOST, но ICC < 0.75 или широких LoA — вывод «эквивалентны в среднем, но не взаимозаменяемы для отдельного владельца» (для K3 inference — только с подтверждением пользователя).
- `p > 0.05` в тесте на *различие* само по себе гипотезу не подтверждает.

#### 5.3.7. 152-ФЗ

Тексты чата и транскрипты голоса — ПДн свободного содержания: отдельное согласие на обработку переписки/голоса (версия, фиксация, отзыв), хранение сырого текста в РФ-контуре, в аналитику — только псевдонимизированные `item_id` + скоры + `channel`; encoder для embeddings — локальный или РФ-хостинг (зарубежный API — только с явной оговоркой). См. [personal-data-152-fz](../../../../wiki/concepts/personal-data-152-fz.md).

## 6. Сравнение РФ vs референс — проверка H₁-transfer

1. Доменные скоры пилота РФ vs референс (short C-BARQ / Bohland post-adoption) по ключевым доменам.
2. TOST / заранее заданный δ, α = 0.05.
3. Нужно для обоснования переноса моделей/порогов с зарубежных данных на РФ-пилот.
4. **Решение по H₀:** хотя бы по одному ключевому домену `|Δ| ≥ δ` (неэквивалентность). `p > 0.05` в тесте на различие ≠ подтверждение эквивалентности.

## 7. Human-eval K5-RAG — проверка H₁-human-eval

1. Один набор запросов; ответы: K5 с RAG (wiki) vs baseline без RAG.
2. Слепое pairwise A/B экспертами; ничья ≠ предпочтение («нет предпочтения»).
3. Доля предпочтений K5-RAG ≥ 70% и значимо выше 50% (α = 0.05).
4. **Решение по H₀:** доля предпочтений K5-RAG ≤ 50% **или** < 70%.

## 8. Эффект приложения на адаптацию — минимальный сдвиг для успеха (H₁-effect)

Дизайн: рандомизация 40 + 40 владельцев (контроль — только анкета; группа — анкета + приложение), стратификация по приюту и первому опыту владения; C-BARQ(S) на 7-й и 30-й день; основной анализ — ANCOVA:

$$
X_{i,d}^{(30)} = \beta_0 + \delta_d \cdot \mathrm{App}_i + \beta_1 X_{i,d}^{(7)} + \varepsilon_i
$$

Первичные домены (фиксируются до сбора): проблемы разлуки, страх незнакомцев. Расчёт порогов и MDE по дисперсиям Bohland — [app-effect-rct-power](../../../../wiki/ml/app-effect-rct-power.md).

### 8.1. Минимальный сдвиг и MDE — разные величины

- **Минимальный сдвиг для успеха** $\varepsilon_d$ (SESOI, smallest effect size of interest) — наименьшая разница изменений домена $d$ между группами, которую владелец и кинолог считают практически важной. Свойство предметной области; от объёма выборки не зависит.
- **MDE** — наименьший истинный эффект, который дизайн обнаружит с мощностью 80%. Свойство дизайна:

$$
\mathrm{MDE}_d = \left(t_{1-\alpha/2} + t_{1-\beta}\right)\cdot SE_d
$$

Порядок работы: сначала фиксируется $\varepsilon_d$, затем дизайн подбирается так, чтобы $\mathrm{MDE}_d \le \varepsilon_d$. Использовать MDE как критерий успеха нельзя: тогда «успехом» становится любой эффект, который удалось заметить.

$\varepsilon_d$ фиксируется **до сбора данных** (pre-registration) вместе с первичными доменами и направлением эффекта. Для проблемных доменов ожидается $\delta_d < 0$; $\varepsilon_d > 0$ задаётся как модуль.

### 8.2. Оценка $\varepsilon_d$

MCID для C-BARQ в литературе не установлен, поэтому $\varepsilon_d$ оценивается в проекте. Приоритет источников:

1. **Якорный метод (предпочтительно).** На 30-й день владелец отвечает на вопрос-якорь по домену: «По сравнению с первой неделей [проблема] стала: намного лучше / немного лучше / без изменений / хуже». Тогда:

$$
\varepsilon_d = \bar{\Delta}_{d,\ \text{«немного лучше»}} - \bar{\Delta}_{d,\ \text{«без изменений»}}
$$

   Считать по контрольной группе или по пилоту до рандомизации: в группе с приложением ответ на якорь искажён ожиданиями.

2. **Экспертный метод.** Балл домена — среднее $k_d$ пунктов (см. [c-barq-short-42-scoring](../../../../wiki/concepts/c-barq-short-42-scoring.md)). Сдвиг одного пункта на одну ступень шкалы меняет домен на $1/k_d$. Кинологи (3–5 экспертов, 2 раунда Delphi) указывают, сдвиг скольких пунктов на одну ступень практически важен:

$$
\varepsilon_d = \frac{m_d}{k_d}
$$

   где $m_d$ — согласованное число пунктов.

3. **Проверочные ориентиры (не заменяют п. 1–2):**
   - правило Нормана: $0.5 \cdot SD_d$ изменения;
   - шум анкеты для отдельной собаки: $SEM_d = SD_d\sqrt{1-\rho_d}$, $\mathrm{MDC}_{95,d} = 1.96\sqrt{2}\cdot SEM_d$, где $\rho_d$ — test-retest надёжность домена (подвыборка из 5.3.1, п. 5). MDC описывает изменение у отдельной собаки; для разницы средних групп $\varepsilon_d$ может быть меньше MDC, но тогда это обосновывается. Корреляция волн d7–d30 у Bohland — не test-retest: за месяц собака реально меняется;
   - естественное изменение за месяц у Bohland: 0.05–0.3 балла. Значение $\varepsilon_d$ сильно выше естественной месячной динамики требует обоснования.

Итог: $\varepsilon_d$ из п. 1, при отсутствии пилота — из п. 2; значения п. 3 приводятся рядом для сверки, расхождения объясняются в протоколе.

### 8.3. Проверка дизайна

Для каждого первичного домена: если $\mathrm{MDE}_d > \varepsilon_d$, выборка увеличивается (`rct_power_thresholds.py --solve-n` с $\varepsilon_d$ и учётом выбывания).

Пример: проблемы разлуки, SD изменения 0.75; при 40 + 40 $\mathrm{MDE}_{\mathrm{ANCOVA}} = 0.44$. Если $\varepsilon_d = 0.3$, нужно около 120 владельцев на группу (2 первичных домена, выбывание 16%). При фиксированных 40 + 40 честный вывод — «дизайн способен обнаружить только эффекты от 0.44 балла».

### 8.4. Критерий успеха

Оценка $\hat{\delta}_d$ — коэффициент при $\mathrm{App}$ в ANCOVA, $\mathrm{CI}_{95}$ с поправкой Holm–Bonferroni по первичным доменам.

- **Основной (практическая значимость):** $\mathrm{CI}_{95}$ не содержит 0 **и** $\lvert\hat{\delta}_d\rvert \ge \varepsilon_d$ в ожидаемом направлении.
- **Строгий (superiority by margin, вторичный):** весь $\mathrm{CI}_{95}$ лежит за $\varepsilon_d$ (для проблемного домена верхняя граница $< -\varepsilon_d$). Требует $\mathrm{MDE}_d \approx \varepsilon_d/2$.

Устойчивость: Mann–Whitney по $\Delta$, bootstrap-ДИ для $\hat{\delta}_d$.

### 8.5. Решение по H₀

- **H₀ сохраняется**, если хотя бы по одному первичному домену критерий 8.4 (основной) не выполнен.
- Эффект значим, но $\lvert\hat{\delta}_d\rvert < \varepsilon_d$ → «статистически значимо, практически не важно».
- Эффект незначим при $\mathrm{MDE}_d > \varepsilon_d$ → «эффект не обнаружен, дизайн недостаточен», а не «приложение не влияет».

### 8.6. 152-ФЗ

Ответы на якорь и анкеты — ПДн владельца: отдельное согласие на исследование (версия, дата, отзыв), хранение в РФ, в анализ — псевдонимный ID собаки, группа, доменные скоры; ops-база с контактами отделена от обезличенного export. См. [personal-data-152-fz](../../../../wiki/concepts/personal-data-152-fz.md).

## 9. Единый контур оценки качества (артефакты)

```
ingest → clean/harmonize → feature_map → baseline(rule) → train(ML) → evaluate(val)
                                                      ↘ expert accept/safe (test)
text → embed → vector retrieval (пункты шкалы) → NLP scores → TOST vs self-report
wiki → vector RAG → answers → pairwise human-eval
```

| Этап | Гипотеза | Ключевая метрика | Baseline / эталон |
|------|----------|------------------|-------------------|
| Rule-based top-5 | H₁-baseline | macro-F1 ≥ 0.6 | random F1 = 0.125 |
| ML top-5 DT | H₁-plan-DT | Δ_DT ≥ 0.10 vs rule | rule-based; CI желателен |
| ML top-5 LR OvR | H₁-plan-LR | Δ_LR ≥ 0.10 vs rule | rule-based; CI желателен; выбор max(Δ) → quality |
| Эксперт | H₁-quality | accept ≥ ~60–70%, safe ≥ ~97–98%; H₀: accept < 60% или safe < 97% | схема принять/править/отклонить |
| NLP↔форма | H₁-channel | парный TOST по каждому домену (CI₉₀ ⊂ ±δ), δ из test-retest; вторично ICC ≥ 0.75, Bland–Altman, κ | self-report того же владельца |
| РФ↔референс | H₁-transfer | TOST по доменам, δ | Bohland / short C-BARQ |
